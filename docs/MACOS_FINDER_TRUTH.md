# Drift for macOS — Finder truth after native saves

Drift exposes **File → Reveal Last Saved File in Finder** as a confidence feature. That command must point only at output that survived its complete native commit lifecycle. A numbered PNG frame is not a completed sequence merely because its own atomic rename succeeded: later frames can fail, the user can cancel, and rollback can remove every frame Drift created.

## Promotion rules

### Ordinary files

MP4 masters, PNG stills, and portable `.pitched` projects use one save-panel file capability. They become the Finder target immediately after their staged bytes atomically replace or create the chosen destination.

### PNG sequences

A sequence is **provisional until directory release**.

- Each frame still uses exclusive same-volume staging and atomic commit.
- Individual frame commits are tracked inside the selected directory grant but do not replace the previous Finder target.
- Full rollback promotes nothing. The previous completed save remains the Finder target.
- Successful release promotes one surviving frame. Finder selects that frame inside the chosen sequence folder.
- Partial rollback promotes the last surviving Drift-created frame, because residual output genuinely remains on disk and deserves to be discoverable.
- A renderer crash before release is conservative: no provisional sequence frame is promoted. Existing committed frames may remain in the selected folder, but Drift does not call an interrupted sequence “completed.”

This design keeps the menu label accurate—it always reveals a file—and avoids storing hundreds of frame destinations in native history.

## Capability and rollback boundary

The directory grant owns an ordered, bounded-in-practice list of Drift-created committed child names for its own lifetime. It never records pre-existing files. The list changes only after:

1. exclusive atomic frame commit succeeds; or
2. native rollback successfully removes that exact child.

Directory release is rejected while one of its frame writes is still open. On release, native code walks committed child names newest-first and promotes only an existing, non-symbolic-link file. Revoking all capabilities after WebKit termination discards provisional tracking without promoting it.

## Native falsification

`NativeFileBroker.runSelfTest()` proves:

1. a normal replacement promotes its destination once;
2. a first save replaces that Finder target;
3. committing a provisional sequence frame does not change the target;
4. fully removing the committed frame and releasing its directory leaves the previous target untouched;
5. committing a frame in a fresh directory still does not promote before release;
6. releasing that successful directory promotes the surviving frame exactly once;
7. an aborted frame never appears at its final path;
8. commit-time collision preserves the intruding file and never promotes generated bytes;
9. directories with provisional committed children are not selected as ordinary grant-eviction victims.

The independent source checker also requires exactly two native promotion paths: ordinary atomic file commit and released sequence survivor. Any reintroduction of per-frame promotion fails `npm run check` before packaging.

## Manual Mac review

On a physical Mac:

1. save a `.pitched` project and confirm Reveal selects that project;
2. export a still and confirm Reveal advances to the still;
3. begin a PNG sequence, cancel after several frames, confirm rollback removes them, then confirm Reveal still selects the earlier still;
4. complete a PNG sequence and confirm Reveal selects its last frame in the chosen folder;
5. force one rollback deletion to fail and confirm Reveal selects a genuinely surviving frame;
6. externally delete the revealed file and confirm Finder fails safely rather than exposing another path;
7. force WebKit termination after a few sequence commits and confirm Drift does not claim those provisional frames as a completed save;
8. repeat with file and folder names containing spaces, Unicode, and long—but valid—leaf names.

## Deliberate limits

This pass does not add a persistent recent-export database, inspect user directories recursively, remember paths across app launches, or promote an interrupted sequence. The native process retains only the current in-memory Finder target and the provisional child names needed to tell success from rollback during one selected directory capability.
